# UI Node Tree & Notes Exporter v10.11 DeepSeek MMD Preview

## v10.11 DeepSeek MMD Preview

- 在独立“生成 MMD”页接入 DeepSeek Chat Completions API，可直接把当前完整交接文档生成 Mermaid `sequenceDiagram`。
- 每次生成和自动修正都会先向 DeepSeek 提供完整 Skill v1.3 与完整规范 v2.3，要求依次通读两份原文后再读取交接事实并开始写 MMD；不以摘要替代原文。
- API Key 只保存到本机 `figma.clientStorage`，不会写入源码、备注 JSON、组件资料、交接文档或 MMD。
- 网络权限只允许 `https://api.deepseek.com`；除用户主动保存设置或生成 MMD 外，插件不会发送请求。
- 默认模型为 `deepseek-v4-pro` 非思考模式、低温度；可切换 `deepseek-v4-flash` 或手动开启深度思考。
- 请求使用 JSON Output，响应只接受 `mmd / warnings / evidence_gaps`，空响应或无效 JSON 自动重试一次。
- 完整 Skill 与规范共同强调“可以理解、整理、归纳，但不能创造”，禁止擅自补充创建、销毁、新增、删除、刷新、复用、状态机、API、事件、变量或程序算法。
- 生成后执行本地硬规则校验：检查 `sequenceDiagram`、初始摆放阶段、真实节点遗漏、未知反引号节点、资料外程序行为与初始化阶段运行时逻辑。
- 默认在发现高风险问题时自动修正一次；第二次仍未通过时保留结果并明确列出问题，交由人工确认。
- 新增 `tests/deepseek-mmd-guardrails.regression.test.js`，覆盖 API 请求契约、JSON 解析、节点遗漏和防脑补校验。

详细说明见 [`DEEPSEEK_MMD.md`](DEEPSEEK_MMD.md)。

## v10.6：跨 Design 双向工作区快捷导航

- “组件快捷跳转”升级为 **工作区快捷跳转**：主组件与所有关联组件都作为同一个工作区的导航入口，不再只依附主 Design 的当前插件会话。
- 插件会把工作区的轻量导航表保存到本机 `figma.clientStorage`，内容仅包含组件名称、来源 Design / Page、fileKey、原始根节点 ID 与来源链接；不保存其他 Figma 文档内容，也不联网。
- 从主 Design 点击外部组件并打开另一个 Design 后，在目标 Design 打开插件时，如果当前组件属于已保存工作区，会自动恢复同一套快捷导航，因此可以直接从子组件跳回主组件，也可跳到其他关联组件。
- 同一 Design 的目标继续使用 Page / Node ID 直接定位；不同 Design 的目标继续使用随组件资料保存的来源链接打开。
- “关联组件 JSON”新增 `workspaceNavigation` 与 `sourceFileKey`。已有工作区导航会随 JSON 一并携带，导入后也会合并到本机导航缓存，作为跨 Design 恢复的冗余通道。
- 主组件和每个关联组件都保存自己的来源信息；外部组件继续保留原始来源 Node ID，不使用目标 Design 中重映射后的临时 ID 做跨文件定位。
- 当用户主动新增、更新、移除关联组件或修改外部来源链接时，会同步刷新工作区导航；单独打开一个没有关联关系的普通组件不会覆盖已恢复的跨 Design 工作区。

## v9.9：快照顺序强制继承 Figma + 变体解释

- **状态快照树不再通过筛选结果重建后排序。** v9.9 直接沿插件当前节点树遍历输出，并复用节点树的顺序设置，因此“显示 / 隐藏 / Delta”在筛选后仍严格保持当前节点树中的兄弟节点顺序；旧快照中已无法在当前树定位的节点只会追加到末尾并标记 `[旧快照未定位]`。
- **Variant 状态树也复用同一节点顺序设置。** 不再出现节点结构和 Variant/快照树顺序不一致。
- **新增“变体解释（可选）”。** 每个 Variant 都可填写用途说明，例如“常态 / 悬浮态 / 按下态 / 禁用态”。解释会保存到 notes JSON，并进入 AI handoff。
- **纯样式 Variant 仍不展开状态。** 即使填写了“悬浮态”等解释，如果该 Variant 只有颜色、描边、透明度等样式变化而无结构 / 有效显隐变化，仍只输出变体解释，不重复生成状态快照；具体样式由交互说明补充。
- 变体解释优先按 Variant Node ID 恢复；如果设计重建导致 ID 变化，会使用完整 Variant 标签作为兜底匹配。

- **Component Set 会被明确标记为 `[Figma 变体组件]`。** 组件编辑上下文、状态页、关联组件列表、AI handoff 都会保留变体组件身份，避免节点树只显示基准结构后看起来与普通组件无区别。
- **Variant 不再自动等同于业务状态。** 插件只把相对基准存在“结构变化 / 有效显隐变化”的 Variant 作为交互状态展开。
- **无结构 / 有效显隐差异的 Variant 不重复列状态。** 这类 Variant 通常只是颜色、描边、透明度等样式变化；插件只做轻量统计/列名，具体样式调整直接在交互说明中补充。
- **节点结构仍只输出一次。** AI handoff 会把变体组件的节点树标题标成 `【节点结构 · 基准变体 ...】`。
- **AI handoff 新增 `【Figma 变体信息】`。** 始终保留 Component Set 身份、Variant 总数、变体属性和结构基准；只有检测到业务层级/显隐差异时才额外输出 `【Figma 变体状态】`。
- **交接检查区分 Variant 总数、真正进入交互状态的 Variant、未展开 Variant。**
- 纯样式 Variant 的判断基于插件当前用于交互图的维度：**节点结构 + 有效显隐**。如果某个 Variant 的样式差异需要程序关注，请在交互说明中明确写对应节点及调整内容。

## v9.5：状态快照树形展示与根节点去重

1. **当前组件根节点不再重复显示**
   - 状态快照顶部已经显示 `当前组件：xxx`，因此组件根节点本身不再进入状态快照的业务节点计数、完整显隐列表和 Delta。
   - 根节点仍保留在快照内部，用于计算子节点的 `effectiveVisible`；如果根节点隐藏，所有后代仍会按有效显隐视为隐藏。

2. **“显示 / 隐藏”改为真实节点树展示**
   - 不再把节点平铺成一长串。
   - 父级隐藏导致的子级隐藏仍全部保留，并按真实父子层级展示，方便直接看出继承关系。
   - 如果某个父级只是为了补全路径而出现在另一类显隐树中，会标记 `[结构路径]`；该标记只表示层级路径，不代表父级属于该显隐状态。

3. **状态 Delta 同样按树形组织**
   - `显示 → 隐藏`、`隐藏 → 显示` 分组后按节点树展示。
   - 不压缩父级导致的子级变化：父级与子级的有效显隐变化都会保留，重点是通过树结构让关系更直观。

4. **交接文档 TXT 与插件状态页保持一致**
   - 完整快照和 Delta 都使用同样的树形表达。
   - 当前组件名只在组件/状态上下文处出现，不在每一条状态节点中重复。

## v9.4：状态快照有效显隐修正

1. **父级隐藏时，子级在状态快照中同步视为隐藏**
   - 插件内部同时保存 `rawVisible`（节点自身 Figma visible）与 `effectiveVisible`（考虑全部父级后的有效显隐）。
   - 交接文档、状态计数和状态 Delta 使用 `effectiveVisible`。
   - 例如父级为隐藏、两个子级自身眼睛仍为显示时，快照结果会把父级与两个子级都视为隐藏，不再出现“父级隐藏、子级显示”的业务错误。

2. **保留节点自身显隐，不丢失 Figma 原始状态**
   - `rawVisible` 仍保存在快照 JSON 中，因此以后父级重新显示时，可以正确恢复每个子节点自身原本的显示/隐藏状态。
   - 节点树中的 `[当前Figma：隐藏]` 仍只表示节点自身的当前 Figma visible，不等于业务默认状态。

3. **状态快照改为可选的复杂状态辅助工具**
   - 简单规则，例如“只显示 `img_skill`，其他层级隐藏”，直接写交互说明即可。
   - 多节点、多层级、多状态联动时再使用状态快照。
   - 删除“交互说明有显隐但状态快照为 0”的轻提示；0 个状态快照不代表交接不完整。

4. **交接文档规则同步**
   - 有状态快照时：复杂显隐优先读取快照的有效显隐 Delta。
   - 无状态快照时：直接使用交互说明中明确的显隐规则。
   - 父级隐藏后，后代节点的业务可见性按隐藏处理。


## v9.3：交接信息质量优化

1. **当前 Figma 隐藏与业务默认隐藏分开**
   - 节点树不再输出模糊的 `(隐藏)`。
   - 改为 `[当前Figma：隐藏]`，明确它只是导出当下 Figma 的 `visible=false`，不能自动等同于“业务默认隐藏”。
   - 备注编辑和节点树查看页也会显示 `[当前Figma隐藏]` 标记。

2. **关联组件增加“关系说明”**
   - 在关联组件管理页可填写可选关系，例如：`上游调用主组件`、`主组件调用`、`关联组件内部复用`。
   - 关系属于当前主组件工作区，不写进关联组件自身的独立备注语义中。
   - 主组件 `.notes.json` 会在 `linkedComponents[].relation` 保存关系，重新导入时自动恢复。
   - 最终 交接文档 TXT 会在关联组件列表和每个关联组件章节中输出该关系。

3. **已忽略节点增加审计清单**
   - 交接检查除显示“明确忽略节点合计”外，还会列出每个已忽略节点的所属组件和完整路径。
   - 已忽略节点仍不会进入正常业务节点说明；该清单只用于检查是否误点忽略。

4. **状态快照轻提示**
   - 如果交互说明中检测到“显示 / 隐藏 / 显隐 / 只显示 / 不显示”等描述，但整个工作区状态快照为 0，会给出轻提示。
   - 该提示不阻止导出，也不要求必须创建状态快照。

5. **完全兼容 v9.2 / v9.1 备注 JSON**
   - 旧 JSON 没有 `relation` 时按空关系处理，不影响原有节点备注、交互说明和状态快照。

## v9.2：跨组件同名检查修正

交接检查现在区分三种情况：

1. **真实跨组件同名**：同一个业务节点名在多个组件中都作为未忽略业务节点存在，且无法判定为同一个可复用组件的本体/实例关系。此时继续告警，需要结合组件上下文判断。
2. **已忽略节点造成的同名**：已忽略节点不参与“跨组件同名”告警；只有当交互说明引用只命中已忽略节点时，才按“已忽略引用”单独提醒。
3. **组件本体 / INSTANCE 实例同名**：例如 `frame_hud_dynamic_attribute_head` 同时作为关联组件根节点存在，又作为另一个组件里的同名 `INSTANCE` 子组件存在。这是正常的组件调用关系，会显示为“正常组件本体/实例同名”，不视为冲突。

这样可以避免类似 `frame_buff` 因另一个组件中的已忽略同名节点而误报，也不会把正常的可复用组件实例关系当成歧义。

## v9.1：子组件边界

当前编辑组件内部遇到 Figma `INSTANCE` 子组件时，插件只记录这个子组件实例本身，不再把实例内部所有层级重复展开。

例如主组件真实结构：

```text
frame_reward
└─ frame_hud_erosion_reward
   └─ frame_gain
      ├─ img_gain_money
      └─ txt_gain_num
```

主组件页只记录：

```text
frame_reward
└─ frame_hud_erosion_reward [子组件]
```

`frame_hud_erosion_reward` 内部结构由“关联组件”独立编辑和说明。状态快照同样遵守这个边界：主组件只比较子组件实例整体的显示/隐藏，不会把其内部节点重复列进状态差异。

如果当前编辑根节点本身就是一个 `INSTANCE`，它仍然可以作为独立组件展开；只有“当前根组件内部的嵌套 INSTANCE”会被截断。

## v9.1：当前查看状态与基准状态分离

- 第一个状态仍会自动成为基准。
- 新建哪个状态，就自动展开并查看哪个状态。
- 覆盖哪个状态，就继续停留在那个状态。
- “设为基准”只改变比较基准，不会把界面跳回基准状态。
- 点击状态名称可切换当前查看状态。
- 删除当前查看状态后，会自动切到剩余的最新状态。

因此“基准状态”只承担 Delta 比较职责，不再控制 UI 默认展开哪一张状态卡。

## v9 新增：Figma 状态快照

新增 `状态快照` Tab。进入该 Tab 后，插件会临时固定当前组件：你可以在 Figma 中选择子层级、切换眼睛显隐，而不会把当前插件根组件误切成子层级。离开状态页后恢复原来的选区跟随逻辑。

推荐流程：

1. 在 Figma 中选中主组件或进入某个关联组件的独立编辑页。
2. 在 Figma Layers 中把这个组件的显隐摆成一个具体状态。
3. 打开插件 `状态快照`，输入状态名，例如 `双方均未争夺`。
4. 点击 `+ 记录当前 Figma 状态`。
5. 第一次记录会自动成为基准状态。
6. 回 Figma 修改显隐，摆出下一状态，例如 `我方获胜`，再次记录。
7. 插件自动显示与基准状态之间的 `显示 → 隐藏` / `隐藏 → 显示` 差异。
8. 某个状态后来改了，直接点 `覆盖记录`，不用删掉重建。

状态快照不会向 Figma 写任何数据。v9.4 起同时记录节点自身 `rawVisible` 与考虑父级后的 `effectiveVisible`，AI 显隐使用有效显隐。

## 状态比较

- 每个组件可以有多个状态。
- 第一个状态自动设为 `基准`。
- 可以单击 `设为基准` 更换全局基准。
- 每个非基准状态还可以单独选择 `对比基准`，适合“即将超时”这类叠加状态。
- 如果两个快照之间节点结构发生变化，也会显示 `新增节点` / `当前缺失`。
- 每个状态有一个可选的 `状态补充` 输入框，可写触发条件、动态值、动画等。

## 锁定 / AI 忽略规则

- 锁定节点及其锁定子树仍不进入日常节点树和 AI 状态差异。
- AI 忽略节点仍会被快照原始数据记录，但默认不输出为业务显隐变化。
- 父级忽略不代表子级忽略；每个节点的 AI 忽略状态仍独立。

## 交接文档 TXT

最终 交接文档现在会聚合：

- 主组件节点结构与中文作用
- 关联组件节点结构与中文作用

- 状态之间的显隐 Delta
- 状态补充
- 交互说明需求
- 交接检查

对于复杂状态，交互说明无需重复快照已经明确的大量显隐；对于简单状态，也可以完全不录快照，直接在交互说明中写清显隐。交互说明还应补充 Figma 静态状态无法表达的内容：

## v7 新增：关联组件

一个交互工作区由：

```text
1 个主组件
+
0~N 个关联组件
+
1 份共享交互说明
```

组成。

例如：

```text
主组件：
frame_hud_erosion_contention

关联组件：
frame_hud_erosion_reward
frame_hud_erosion_avatar
hud_common_tips_buff_04
```

### 添加关联组件

进入 `关联组件` 页签后有两种方式：

```text
+ 添加当前文件组件
+ 导入外部组件
```

**同一 Figma Design：**点击“+ 添加当前文件组件”后，可以停留在当前 Page，也可以切换到其他 Page，再选择 1 个 Frame / Component / Instance / Component Set。主组件不会被替换，插件会把所选组件加入当前工作区并独立编辑。

**另一个 Figma Design：**先在来源 Design 中选择目标组件并点击“导出关联组件 JSON”，得到 `xxx.component.json`；回到当前 Design 后点击“+ 导入外部组件”并选择该文件。外部组件会作为独立关联组件加入工作区，但不会尝试在当前 Design 中定位其 Node ID。

如不想继续当前文件的选择模式，可点击 `取消选择`。

## 主组件和关联组件不会混在一棵备注树

主组件：

```text
frame_hud_erosion_contention
├─ frame_left
├─ frame_right
└─ frame_reward
```

关联组件 `frame_hud_erosion_reward` 会单独编辑：

```text
frame_hud_erosion_reward
└─ frame_gain
   ├─ img_gain_money
   └─ txt_gain_num
```

不会显示成：

```text
frame_hud_erosion_contention
└─ frame_hud_erosion_reward   ← 不会这样错误混入
```

编辑关联组件时，顶部会明确显示：

```text
关联组件：frame_hud_erosion_reward
主组件：frame_hud_erosion_contention
```

并提供：

- `主组件`
- `← 返回关联组件`

两个快捷入口。

## 关联组件管理页

`关联组件` 页面只显示组件级列表，不直接把所有子层级摊在一起：

```text
frame_hud_erosion_reward
Page: HUD · 12 个可显示节点
[编辑] [移除]
```

点击 `编辑` 后才进入该组件自己的备注树。

`移除` 只会把它从当前交互工作区移除，不修改 Figma，也不会立刻销毁本次插件会话中的备注状态。

## 交互说明属于整个工作区

交互说明不再属于某一个关联组件，而是属于：

```text
主组件 + 所有关联组件
```

因此你可以在同一份交互说明中写：

```text
我方获胜后显示 `frame_reward`。

奖励列表项使用 `frame_hud_erosion_reward`，
其中 `img_gain_money` 显示金币图标，
`txt_gain_num` 显示奖励数量。
```

在主组件或任意关联组件的编辑页点击 `引用`，都会把真实节点名插入同一份交互说明编辑器。

## 交接文档检查覆盖所有组件

v7 的检查范围是：

```text

+
所有已加载关联组件
+
交互说明
```

会检查：

- 所有组件中的未填写中文作用节点；
- 交互说明反引号引用是否存在；
- 引用是否只命中了已忽略节点；
- 同一节点名是否同时存在于多个组件；
- 交互说明是否为空。

如果出现跨组件同名节点，会提醒：

```text
[同名] `txt_num`：
frame_component_a / frame_component_b
```

- 展开 / 收起
- 全部展开
- 全部收起
- 展开至 2 层
- 搜索

### 节点类型

`FRAME / INSTANCE / RECTANGLE / TEXT` 等类型内部保留用于匹配，UI 默认隐藏，AI/TXT 不输出。

## 安装

1. 解压插件目录。
2. 打开 Figma Desktop。
3. `Plugins -> Development -> Import plugin from manifest...`
4. 选择本目录的 `manifest.json`。

manifest ID 与之前版本保持一致，可直接重新导入开发插件。

## 隐私与网络

插件：

- 不使用 `setPluginData`；
- 不写入 Figma 节点；
- 不修改共享设计稿；
- 不使用 WebSocket / CDN；
- 只有用户主动点击生成 MMD 时才使用 `fetch` 请求 DeepSeek；
- API Key 只写入本机 `figma.clientStorage`，不会进入导出资料；
- 不连接外部 Figma 服务。

`manifest.json`：

```json
"networkAccess": {
  "allowedDomains": ["https://api.deepseek.com"]
}
```
